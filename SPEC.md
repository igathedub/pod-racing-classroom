# Pod Racing Classroom — implementation contract

A real locally hosted classroom site for Python learners. Beginner CodinGame-like two-line observation and one-line action, NOT a claim of an exact official engine. Each student controls one pod; five-pod final is an explicit classroom variant. English/German UI. Teacher-selected submission window (two hours by default). All student execution exclusively in restricted Docker; never a host subprocess fallback. Pure trusted reference bots are allowed for tests/demo. No scraping CodinGame.

## Engine Python API
`make_tracks(seed: int = 2026, count: int = 3) -> list[dict]`: dict keys id, name, checkpoints list [[x,y],...]. Course width16000 height9000, checkpoint_radius600, pod_radius400, rotation18deg/turn except first unrestricted, friction.85, thrust integer0..100, one BOOST650 per pod per race. Deterministic 2-lap races. Checkpoint crossing along segment (not just endpoint). Practice, qualification and final are always collision-free: pods pass through one another without impulses, blocking or movement effects. All other physics stay unchanged. SHIELD remains accepted with 3-turn no thrust; no collision-defense effect. Finishing/timeout deterministic. No external assets or engine copying without license attribution.
`run_race(entries: list[dict], track: dict, *, laps: int=2, max_turns: int=700, on_frame=None, runner_factory=None, input_protocol: str | None=None) -> dict`.
`advance_turn(pods: list[Pod], checkpoints: list, *, laps: int=2, turn: int=1) -> None`. Neither signature accepts a collisions option. New replay metadata always records `collisions:false`; historical saved replay metadata and frames are not rewritten.
Entries keys id, alias, code (str), optional `kind:'reference'` (trusted built-in bot; kind:'student' default). Calls factory(entry) or arena.bots.make_runner(entry). Runner methods `act(observation: str, first: bool=False)->str`, `close()`. First turn observation two newline-terminated lines `x y checkpoint_x checkpoint_y distance relative_angle\nopponent_x opponent_y\n`, nearest other pod in multiplayer; no bootstrap track inputs. Commands `target_x target_y thrust` plus optional label ignored. Proper error classification malformed/timeout/crash/output limit; invalid bots disqualified race continues.
Replay/result dict keys `id` UUID, `track` original dict, `laps`, `max_turns`, `collisions`, `status:'finished'`, `winner_id` nullable, `entries:[{id,alias}]`, `frames:[{turn:int,pods:[{id,alias,x,y,angle,vx,vy,next_checkpoint,passed,finished,disqualified,error,boost_available}]}]`, `results:[{id,alias,place,finished,disqualified,error,turns,passed,distance_to_checkpoint}]` sorted valid finishers then DNF progress then disqualified. `on_frame(frame)` callback every turn; exceptions must close all runners in finally. Store finite numbers only. Qualification reference opponent is allowed; all new races use non-interacting ghosts.
`arena.bots.sandbox_status() -> dict` keys available(bool), detail(str), image(str). Image name `pod-classroom-bot:local`. Must check Docker daemon AND image without pulling/building in HTTP handlers. Container runner startup code supplied via first stdin JSON line to boot.py; subsequent stdin is game's observations. Restricted no networking/host mounts/read-only/drop caps/nonroot/PID-memory-CPU limits/tmpfs and command array no shell. Timeout bounded startup and per turn, cap stdout and stderr, docker rm -f in cleanup. Tests can inject fake runners; Docker integration pytest marker.

## Backend API and persistence
FastAPI; sqlite persisted under data/ (env POD_DATA_DIR override); all IDs UUIDs filenames never aliases. Teacher secret generated on first launch, stored config only, printed server console; `X-Admin-Token` header on admin mutations/teacher reads. NOT exposed via public state. Admin page asks token localStorage/sessionStorage; code/claim tokens not in leaderboard.
Student submission `POST /api/submissions` JSON `{alias,code,claim_token?}` returns `{id,alias,claim_token,version}`. case-insensitive unique alias, claim token required to replace same submission, no takeover; alias1..24 allowed letters/digits/space/_/- (unicode letters okay), code <=32KiB valid Python syntax (AST parse only never exec), forbid updates after deadline/closed/frozen. Teacher starts session -> open, deadline epoch seconds now+duration. On first installation submissions CLOSED until teacher starts; restart retains deadline. Public state deadline expired treated closed regardless worker/timer. JSON errors understandable.
`GET /api/state` -> `{session:{status:'waiting'|'open'|'closed'|'qualifying'|'qualified'|'final'|'finished',deadline:null|float,duration_seconds:7200},submissions:[{id,alias,version,submitted_at}],leaderboard:[{id,alias,rank,completed_tracks,total_turns,progress,disqualified,error?}],job:{status:'idle'|'running'|'finished'|'failed',phase:'qualification'|'final'|null,completed,total,message,error?},sandbox:{available,detail,image},active_replay_id:null|string,replays:[{id,title,kind,created_at,winner_alias?}],finalists:[{id,alias}],champion:null|{id,alias},server_time:epoch seconds}`.
`GET /api/starter` plain Python file download; `GET /api/rules` -> JSON basic protocol; `/` student page, `/teacher` teacher dashboard, `/projector` large race viewer all same SPA index.
`POST /api/admin/session/start` `{duration_seconds:7200}` -> session; `POST /api/admin/session/close` -> session; `POST /api/admin/qualify` ->202 job starts background worker single job lock, closes/freezes submissions, checks Docker available BEFORE change. Each student runs SAME 3 courses (make_tracks), identical starting position against trusted reference ghost, without collisions. Save immutable snapshot of submissions for this competition; rank completed_tracks desc, total_turns asc, aggregate progress desc for DNF, never put invalid above valid. Progress tie deterministic id/alias tiebreak documented. Only no-disqualification entries eligible final. Stream active replay snapshots via callback at most 4Hz; do not serialize frames quadratic every turn. Public `GET /api/replays/{id}` returns full current/finished JSON (bounded at max700 turns and <=5 final pods), includes status:'running' for live. Qualification replay include baseline filtered from leaderboard. `POST /api/admin/final` ->202 races best5 eligible snapshot entries in a single simultaneous race without collisions on deterministic showcase track; need at least2 eligible else409; up to5 if fewer but honest UI. Save full replay and champion from winner; never crown crash/DNF as finished winner unless documented tiebreak rules. `GET /api/admin/submissions/{id}` returns code teacher-only. `POST /api/admin/demo` -> inserts6 sample example bots ONLY if empty waiting session; no fake rankings, run actual qualifiers. `POST /api/admin/reset` `{confirm:'RESET'}` explicit UI confirm, reject active job, new session and clears classroom competition records (not admin secret); tests only. Recovery active job interrupted at restart ->failed not stale running. Max60 submissions, request/output replay size bounded, no public code/secret exposure. CORS disabled, only same origin browser; mutations JSON and protected secret for admin. Do not expose runner traceback/secrets to public.

## Three-track final contract (supersedes the original single-final clauses above)

New competitions use `final_format:'three-track-total-time-v1'`. Qualification keeps the original first three tracks and its ranking rules. The final races the same two-to-five eligible frozen bots on three **other** tracks (Hairpin Run, Diamond Loop, Technical Loop); every race is collision-free. `make_tracks(..., count=6)` supplies the original first three plus three additional tracks. Final totals exclude qualification times completely.

Engine result rows add nullable fractional `finish_time` in simulated turns. A final total exists only for three valid finishes without disqualification. Lowest total wins; exact ties use case-folded alias then UUID. DNF/DQ has no winning total, and if no bot completes all three validly, `champion` is null. Replay presentation speed and machine execution seconds are not scoring units. Display rounding never changes server ranking.

`GET /api/state` additionally exposes `final_tracks:[track,track,track]`, `final_format:null|string`, `final_replay_ids:[UUID,...]` for the **current** series in race order, and `final_leaderboard:[{id,alias,rank,completed_tracks,disqualified,race_times:[float|null,float|null,float|null],total_time:float|null}]`. Before a series these lists may be empty. Final JSON adds `series_index:1|2|3` and `series_total:3`. Metadata titles are `Final {i}/3 · {track[name]} · {n} pods`. Rules add `final_tracks:3`, `time_unit:'simulated_turns'`, and English/German `final_scoring` copy; localization accepts older fixtures without these optional fields and never translates aliases, protocol keys or numeric values.

The frontend provides three keyboard-accessible tabs: qualification ranking, current race positions, and final overall (Final 1/2/3/Total, simulated turns with three displayed decimals, DNF/DQ). Teacher can inspect overall standings anytime. Student/projector aggregate table and champion require all three current replay IDs, viewing the last current final replay with matching metadata and `series_index:3,series_total:3`, playback end, and both job/session finished. Neither a qualifier, a stale/failed series, nor the first or second final reveals the overall result, even when its race winner equals the champion. The last race winner may differ from the overall champion and must be labeled separately. UI presentation hiding is not API authorization.

Legacy competitions without a final format/current-series list retain the original matching-final-metadata/winner/end reveal. Historical contact labels, saved replay bytes and submitted source are preserved; no retroactive rescoring. Submission-duration and invitation-expiry controls remain independent and unchanged. See [docs/three-track-final.md](docs/three-track-final.md) for exact progress text and synthetic verification scope. Existing native/Docker verification reports describe their original tested release; this contract is not evidence of new native execution or deployment.
